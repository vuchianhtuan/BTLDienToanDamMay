## Ubuntu cloud-init test

- Created `tv1-ubuntu-metadata-test` (`1bf9a476-cb54-40a5-915d-13d38538d4bc`) using existing `Ubuntu-24.04`, flavor `ds1G` (1 vCPU, 1 GiB RAM, 10 GiB disk), network `tv1-test-network`, AZ `tv1-az2`. Nova reported ACTIVE on `ip-172-31-1-199`, address `10.73.0.88`.
- Used dedicated key pair `tv1-ubuntu-metadata-key` and a synthetic cloud-config which writes `TV1_UBUNTU_USERDATA_OK` to `/var/tmp/tv1-cloud-init-marker`. Login as Ubuntu using the private test key succeeded through the first test VM. The marker was present, instance-id matched the server UUID, and `cloud-init status --long` reported `done`, `DataSourceOpenStackLocal [net,ver=2]`, no errors or recoverable errors. A separate request from the VM to the OpenStack HTTP metadata endpoint returned 200; cloud-init reported the local datasource.
- On EC2, available RAM was about 1.9 GiB while the image was being prepared and about 1.5 GiB after boot; disk available about 20 GiB after image preparation. Initial boot waited on network setup for over a minute before cloud-init completed. This is a functional test, not evidence that multiple application VMs and an amphora fit under load.
